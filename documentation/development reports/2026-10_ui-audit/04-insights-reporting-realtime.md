## 3. Overlap

- **Insights Reports** (multi-project): counters, species/type/deployment charts, editable layout, deployment + species filters. Unique: cross-project aggregation, the map with species pies and per-day rates, bulk actions.
- **Reporting** (one deployment): species-by-day bar/line with species chips, species totals, CSV, Exports tab. Unique: time series at day granularity (`buildObsSpec` 35-80), the zero-observation state with period and photo count (232-270), the CamtrapDP entry point (which is per project, 400-402, despite the per-deployment page).
- **Realtime**: by-date active deployments, telemetry, 48 h detections, needs-attention list. Unique: everything telemetry.
- **MyData legacy**: a fixed copy of the Insights default dashboard (ObservationReports 245-280 = DEFAULT_WIDGETS 52-60), a plain-circle map, Projects (now Settings), Media (now Annotations), per-row Images/Clusters/Review/UMAP buttons (Clusters and UMAP are reachable from MediaBrowser 1337-1339; Review only from Cluster Review 544).
- **Could be one page**: Insights Reports with `?deployment=` already is per-deployment reporting; add a "detections per day by species" chart kind to `chartSpec` and the Reporting Charts tab is redundant. Exports belong at project level (Settings or Toolkit) rather than under a deployment. Then `/reporting/:id` becomes a redirect to `/insights?tab=reports&deployment=:id`. The legacy page can go entirely.

## 4. Specific checks

- **Insights deployments table paging**: loads every deployment of the selected projects in one request with no range (InsightsPage 68-83, PostgREST cap 1,000), then client-side paging of 50 (378; DataTable 140-141), client sort and search over visible columns (118-137). 100 deployments = 1 request, 2 pages. The ribbon's "N shown" is the unfiltered total (316).
- **DeploymentActionRow / useClusters**: the current `components/data/DeploymentActionRow.tsx` is types and a style only (1-32); the per-row `useClusters` lives in the legacy page (`MyDataPage.tsx:111-112`), one `GET /api/brain/clusters/{id}` per row on first paint (`hooks/useBrain.ts:36-45`), all rows since it has no paging. Insights does not do this.
- **Map with 100 markers / no GPS**: see #12 and #13. Deployments without coordinates are filtered at DeploymentMap 102; zero GPS shows a placeholder (153-168).
- **FieldPage active filter and table width**: active = `deployment_end` null or future (111). The table has 7 columns, not 11 (235-255); at 0.8125 rem it fits 1200 px comfortably (inferred, not rendered). At 800 px tall the heading, 6 KPIs, attention panel and a 420 px map push the table below the fold (inferred).
- **Reporting deployment picker**: none; the id comes from the URL (496-500). Entry points: bulk menu single row (DeploymentBulkActions 180), upload dock (ProgressDock 186), Event Review (391), legacy row menu. No 100-item dropdown, but no way to change deployment either.
- **CamtrapDP state machine** (`CamtrapExportStatus.tsx:99-111`, `useCamtrapExport.ts:124-156`, `lib/camtrapExport.ts:73-84`): nothing → (error: red "⚠ msg", wins over all) → (fallback edge download: green "✓ Download started.") → job queued/processing: dim "⏳ message NN%" polled every 2 s (`useJob.ts:16-20`) → completed: green "✓ Export ready." + "Download again" link; completed_with_errors: amber + link; failed: red. The ZIP auto-saves once per job (useCamtrapExport 133-138). The card button reads "⏳ Preparing…" while running (ReportingPage 459). Scope is the whole project (400-402).
- **CreateProjectModal role check**: none. It takes the first active organisation role of any kind (106, 121-122); the insert is accepted or refused by RLS and the raw message is shown (150-175). Settings gates the button only for the demo (`DemoDisabled`, 263-267).

## 5. Keep

1. Row selection + one Actions menu instead of a per-row button strip, with single-row-only items (DeploymentBulkActions 36-40, 95, 179-187).
2. Delete with undo toast and a refused count (110-131).
3. MoveDeploymentDialog computes real targets from the rule and explains refusals in words; errors mapped by SQLSTATE (MoveDeploymentDialog 228-239; moveDeployment.ts 92-109, 135-146).
4. EditLocationDialog re-reads after save and shows what was stored; Save disabled until dirty and valid (52-59, 137).
5. `DataTable` as the one table primitive (paging, sort, search, selection) and `fetchLiveObservations` paging past 1,000 with `keepPreviousData` so reports do not flash (InsightsPage 166).
6. Realtime subscription filtered to the shown deployments, tab shown only when relevant, legend "N of M have GPS" (FieldPage 143-154; useHasActiveDeployments; DeploymentMap 298).
