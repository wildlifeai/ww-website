`fe/` = `frontend/src/`, `be/` = `backend/app/` (worktree research/ui-audit, origin/dev 77dae73). Read-only.

## 1. Surfaces

**MediaDetail (the viewer, `fe/components/data/MediaDetail.tsx` + `MediaDetailImage.tsx`).** Full-screen modal opened by one click on a grid card (`MediaBrowser.tsx:1476`). For every signed-in role. Default screen: image stage with prev/next arrows, box overlays with a label button per row (`MediaDetailImage.tsx:319-369`); a toolbar of **10 always-on controls** (zoom out, %, zoom in, Reset, brightness slider, contrast slider, Movement, annotation-filter select, Confirm/Confirm all, Add; `MediaDetail.tsx:443-481`) plus **4 more once a row is selected** (Relabel, Box, Blank, Remove; `:483-496`); a 360px sidebar with file name, "Observations (n)", a hint sentence, the Camera AI EXIF panel, the ranked observation cards, a collapsed "Media information" details, and a shortcuts legend (`:198-244`). No feature flag; writes go straight to Supabase (`:303, :326, :365`).

**Bulk label (`BulkLabelModal.tsx`, `MediaBulkActions.tsx`).** Grid-only: select cards, "Actions ▾", "Label as…" (`MediaBulkActions.tsx:149-158`). Modal = one SpeciesPicker + "Nothing (blank)" + Cancel (`BulkLabelModal.tsx:222-255`). Write in `MediaBrowser.tsx:583-613`. Demo-guarded (`MediaBulkActions.tsx:19,92`), not role-guarded. No flag.

**Review Queue (`fe/pages/ReviewQueuePage.tsx`, `/review/:deployment_id`).** One photo at a time, ranked by active-learning score. Reached from My Data "▶ Review (n)" per deployment (`MyDataPage.tsx:135-141`) and the Cluster Review header (`ClusterReviewPage.tsx:544`). Screen: header card (title, "i / n", Exit), preview, AL score bar + reasons, "AI: label (xx%)", one free-text input, 4 buttons (Approve, Reassign, Expert, Skip): 7 controls. Behind `FF_ACTIVE_LEARNING_ENABLED` (default False, `be/config.py:90`; `be/routers/brain.py:468`); the write `/api/brain/review` is behind `FF_WILDLIFE_BRAIN_ENABLED` (`brain.py:481`). Thumbnails need `FF_MEDIA_REGISTRY_ENABLED` (default False, `config.py:89`; `media.py:126`), otherwise a camera placeholder (`ReviewQueuePage.tsx:103-107`). The frontend reads no flags; links are always shown.

**Cluster Review (`fe/pages/ClusterReviewPage.tsx`, `/clusters/:deployment_id`).** Confirm a whole HDBSCAN cluster as one species, or expand it to reassign / flag for expert / publish to iNat. Reached from My Data "◧ Clusters (c/t)" (`MyDataPage.tsx:128-133`), the grid's "Advanced: Review clusters" when grouped by cluster with one deployment (`MediaBrowser.tsx:1335-1341`), Review Queue empty states, UMAP header. **UMAP Explorer (`fe/pages/UmapExplorerPage.tsx`, `/umap/:deployment_id`).** A 900x600 canvas scatter, hover tooltip with cluster id and an 8-char media id (`:112-117`); no click, no link to a photo. **Event Review (`fe/pages/EventReviewPage.tsx`).** **Unrouted**: no import anywhere (`grep EventReview` hits only the file; documented as unrouted in `documentation/onboarding/05-ANNOTATION-WORKFLOW.md:120`). **Dataset Health (`fe/pages/DatasetHealthPage.tsx`, `/intelligence/:project_id`).** 4 stat tiles, alerts, review funnel, AI-vs-human agreement, species coverage. ## 2. Labelling walkthrough (from a grid card)

(a) **Confirm the AI species**: click card, click "✓ Confirm all" (or `C`): 2 clicks, auto-advances (`MediaDetail.tsx:356-375`). Stamps every unreviewed per-model AI row human_reviewed in one update; consensus row untouched (`observations.ts:165-167`).
(b) **Change species**: click card, click the row (sidebar or box label), "🏷 Relabel", type 2+ chars, wait 250 ms, click a suggestion: 4 clicks + typing (`:485, :506-521`). The AI row is overwritten in place (`:514-517`); its original name is gone.
(c) **Mark empty**: click card, "✕ Blank" or `B`: 2 clicks, but only when a row exists; with no selection it blanks `media.observations[0]` (`:378`), raw order, not the ranked card the user sees (`:64-67`). A photo with no rows cannot be blanked in the viewer at all (`:379`); the route is Add → "Add as unknown animal" → Blank (4 clicks), or grid "Label as… → Nothing (blank)".
(d) **Mark a person**: no control. Every write sets `observation_type` 'animal' or 'blank' (`:319, :380, :516`; `MediaBrowser.tsx:595`); CamtrapDP 'human' is never written. Only workaround: relabel as Homo sapiens if it is in `taxa`.
(e) **Count / sex / life stage**: no UI anywhere; display only (`MediaDetail.tsx:97, :105-106`). The grid offers Group by sex / life stage for fields nothing can set (`MediaBrowser.tsx:180`).
(f) **Delete a wrong box**: select the row, then the ✕ at the box corner clears the bbox fields and keeps the row (`MediaDetailImage.tsx:356-366`), or "🗑 Remove"/`Del` deletes the row (members only, `MediaDetail.tsx:406, :492`). 3 clicks; the legend says "Del remove" without saying it removes the observation, not the box.
(g) **50 photos at once**: Ctrl/Shift-click or "All", "Actions ▾", "Label as…", type, click suggestion: 4 clicks + typing; the suggestion click applies immediately with no confirm step (`BulkLabelModal.tsx:234`). Inserts a new human row per photo even when one exists (`MediaBrowser.tsx:588-602`, no dedupe).
(h) **Undo**: none for any label action. `UndoToast` is used only for media, deployment and project deletes (`MediaBrowser.tsx:428`, `DeploymentBulkActions.tsx:93`, `SettingsPage.tsx:154`). Confirm and Blank auto-advance, so the mistake is already off screen.

**Shortcuts.** MediaDetail: Esc, ←/→, +/−/0, M, F, C, B, A, Del/Backspace (`MediaDetail.tsx:386-408`, legend `:238-241`). ReviewQueue: lowercase a/r/e/s only, no Esc (`ReviewQueuePage.tsx:46-56`). ClusterReview, EventReview, SpeciesPicker: none. The picker has no keyboard navigation: Enter does nothing, a suggestion is mouse-click only (`SpeciesPicker.tsx:182`), so a keyboard-driven session breaks at every relabel. Verbs differ: `C` confirms in the viewer, `a` approves in the queue; `A` adds in the viewer.

**Four AI rows (SpeciesNet, BioCLIP, camera, consensus).** The sidebar lists them ranked by reviewed-then-probability (`:64-67`), each with "⚙ AI 87%" (numeric, `:91-93`), an origin badge, name, type, "▭ box" and "🤖 classified_by" (`:86-111`). Problems: SpeciesNet, BioCLIP and consensus all read "☁ Cloud AI" (`observations.ts:115-121`; `source_model_version` is never shown); nothing marks which row is the card's verdict, since the viewer never calls `photoVerdict` (only the grid does, `MediaBrowser.tsx:1020`); the camera's scores appear twice when a Camera AI row was reflected (EXIF panel `:125-148` plus the row); box labels on the image show name + % per row on one box (`MediaDetailImage.tsx:341-354`), so three labels stack over one animal. Legible, but the reviewer must infer the verdict. The AI-row percentages (confidence) and the review state are shown; the consensus row's reasoning is not.

## 4. Overlap

- **Review Queue vs viewer**: both are "one photo, accept or correct the AI label"; the viewer has boxes, zoom, filmstrip, taxon picker, shortcuts; the queue adds only AL ordering and a worse input. Direction: fold AL score into the grid as a sort (or "Needs review first") and open the viewer; retire `/review`.
- **Cluster Review vs grid "Group by cluster"**: the grid already groups by cluster with a threshold slider and bulk "Label as…" (`MediaBrowser.tsx:180, :1321-1341`). Cluster Review adds tiered review depth, expert flag, iNat publish, "Run Wildlife Brain". Direction: a "Confirm cluster as…" action on the grid's group header; keep the page as an advanced tool reachable from the grid only when a run exists.
- **UMAP**: hover-only, no path to a photo; three entry points. Hide by default (admin/advanced) or remove.
- **Dataset Health vs Insights**: funnel and species counts duplicate Insights; agreement is the only unique number and it is mis-measured (#6). Hide the entry unless enabled.
- **Event Review**: delete.

## 5. Keep

- `confirmAllTargets` + batched Confirm all with one request and auto-advance (`MediaDetail.tsx:356-375`).
- `groupByBox`: one box per animal with a label per model row, label click selects the row (`MediaDetailImage.tsx:319-355`).
- Movement compare and the prefetched filmstrip with status dots (`MediaDetailImage.tsx:32-168`).
- SpeciesPicker's taxon_id contract with iNat lineage registration and local-first fallback (`SpeciesPicker.tsx:123-151`).
- `deleteObservation` throwing on 0 rows (`observationWrites.ts:19-23`): the pattern the other writes need.
- Cluster Review's tiered review-depth badge (bulk / sample / full) is a good scale idea (`ClusterReviewPage.tsx:157, :256-260`).

## 6. Open questions

1. Is the intended provenance model "human edits the AI row" (viewer) or "human adds a verdict row" (bulk, cluster, queue)? Everything in CONSISTENCY hangs on this.
2. Should `project_viewer` be refused by the brain/intelligence write routes, or is the viewer role meant to be API-writable? (#3 is inferred from `authz._has_access`; not run.)
3. `_ai_human_labels` selects an observations column `confidence` while the frontend reads `classification_probability` (`active_learning.py:112` vs `MediaBrowser.tsx:154`): same column, or a silent 0.0?
4. Which flags are on in production (registry, active learning, intelligence)? It decides whether Review Queue, Cluster thumbnails and Health are live features or dead links today.
5. Is CamtrapDP `observation_type='human'` and `count` wanted in the UI, or deliberately out of scope?
