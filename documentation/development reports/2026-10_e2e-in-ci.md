## What was there

`e2e/` held four Playwright specs written from the source against the live DOM (smoke, demo
session, SD-card upload with EXIF binding, LoRaWAN realtime). No workflow ran them: they ran
from a laptop against whatever `e2e/.env` named, and the README expected a calibration pass.
`ci.yml` covered lint, pytest with Supabase mocked, vitest and the Vite build;
`backend-integration.yml` was the one check against a real database.

## Decisions

- **Target the Cloudflare Pages preview, not a build on the runner.** Every branch already
  gets a deployed frontend; Cloudflare posts a GitHub deployment per build, and the workflow
  triggers on its success and takes the URL from it. The bundle under test is the one users
  get. Production deployments are skipped: the seeded account lives on dev.
- **Smoke and demo on every preview, upload and LoRaWAN by hand only.** The last two write to
  the dev database and storage.
- **Traces and video off in CI.** A trace records the password typed into the login form, and
  the artifacts of a public repository are public. The failing page's URL, console errors and
  text go into the job log instead (`e2e/helpers/test.ts`).
- **Count what ran.** The specs skip themselves without env; the workflow fails when the junit
  report holds nothing but skipped tests. Same lesson as ww-mobile-app's E2E job, which
  reported green for months while running nothing.
- **Warm the API inside the first test.** The dev API scales to zero; the smoke's API test
  polls `/docs` for up to three minutes so the cold start is not charged to a page test.
- **Accessibility as a separate advisory job**, named so, with axe-core on the public pages,
  serious and critical only. It becomes blocking once the pages are clean.

2. Calibrate the selectors on the first red run (the README expected one pass).
3. A hermetic full-stack job beside `backend-integration.yml`: local Supabase from ww-backend,

   The only E2E that tests the backend half of a pull request; the candidate for a required
   check.
4. Post-deploy and nightly full suite against dev, with cleanup of what a run created.
5. Cheap checks: an OpenAPI snapshot diff, a docs link validator like ww-mobile-app's, advisory
   `npm audit` and `pip-audit`.
6. Make the smoke required after a green week.
